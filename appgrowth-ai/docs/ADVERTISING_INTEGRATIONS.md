# Advertising and analytics integrations

All adapters implement `AdvertisingProvider` (`apps/api/src/modules/integrations/providers/types.ts`). Availability for
customers requires **both** the `integration.<key>` feature flag and the platform credentials. Readiness shown to customers
stays "implemented, awaiting live verification" until a live test passes; the Super Admin changes it in Admin → Integrations.

| Platform | Auth | Campaign type | What's implemented | To go live |
|---|---|---|---|---|
| Google Ads (REST `v22`, configurable) | OAuth 2.0 + PKCE, `adwords` scope, developer token | App campaigns (MULTI_CHANNEL/APP_CAMPAIGN), install-optimised, target CPA | accounts, permissions, create (budget, campaign, geo/language criteria via GAQL lookups, ad group, app ad text assets), status, budget, metrics (GAQL) | OAuth client, Basic-access developer token, OAuth consent verification |
| Apple Ads (Campaign Management API v5) | OAuth client credentials, ES256 client secret (key pair generated by AppGrowth) | Search results, iOS only | ACL, permissions, create campaign + Search Match ad group, status, budget, reports | a customer API user to verify |
| Meta (Marketing API, Graph `v23.0`) | OAuth, long-lived token (≈60 days, reconnect reminders) | OUTCOME_APP_PROMOTION, APP_INSTALLS ad set | accounts, permissions, campaign + ad set, status, budget, insights (mobile_app_install, country breakdown) | Meta app with Advanced Access for ads_management/ads_read; ad creative upload |
| TikTok (Business API v1.3) | OAuth (auth code → long-lived token) | APP_PROMOTION / APP_INSTALL | advertisers, campaign + ad group, status, budget, integrated reports | approved developer app; video ad upload |

Idempotency on create: every platform campaign name carries `[ag:<key>]`; a retried launch finds and reuses it.
Errors are classified (auth, permission, rate limit, transient, invalid): transient → retried with backoff;
auth/permission → account marked EXPIRED/ERROR, automation for it disabled, customers notified.

## Store data
iOS: iTunes Lookup (public). Android: Google Play Developer API (`androidpublisher`, read-only edits) with the app owner's
service account; package existence is checked by the HTTP status of the public Play page (no scraping).

## Attribution sources (per app)
Signed webhook (any MMP/SDK/server; see API_DOCUMENTATION.md) · AppsFlyer Pull API raw installs (user-level) · Adjust
Report Service (aggregate) · GA4 Data API / Firebase (first_open aggregate, service account). Tokens are stored encrypted.

## Setup checklists
Shown in the product (Integrations page → "Setup checklist") and in each adapter's `setupChecklist()`.
